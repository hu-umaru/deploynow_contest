# 量子ビート工房 / Quantum Beat Studio

**知っている曲が、まだ知らない音楽になる。楽譜を量子ゲートに変えて、1拍ごとにリミックス。**

5量子ビット × 16拍のブラウザ作曲アプリです。MusicXMLのピアノ譜を取り込み、原曲と量子版を同じ音色・テンポで聴き比べられます。外部API・アカウント・有料音源は不要。ブラウザ内の量子シミュレーターとWeb Audioだけで動きます。

## まず聴いてみる

1. **「歓喜の歌」「きらきら星」** の譜例を選ぶ。
2. **A 原曲を聴く** → **B 量子版を聴く**。**A → B 交互に聴く**なら4小節ずつ自動交代。
3. **変換のみ / ゆらぎ / デュエット / リズム崩し**を切り替えて、メロディの変わり方を聴く。
4. **ゆらぎ量**や個別の量子ゲートを変えてリミックス。
5. 気に入ったら**演奏を固定**し、**↓ 保存**から楽譜とゲートをJSONに保存。

譜例は既知の旋律を新しく入力し、簡単な左手伴奏を付けた独自の4小節アレンジです。第三者の録音や市販楽譜を同梱していません。音色はピアノ風の**合成音**です。

## 起動

Node.js 22以上。アプリの外部依存パッケージはありません。

```bash
git clone https://github.com/hu-umaru/deploynow_contest.git
cd deploynow_contest
npm ci
npm run dev
```

http://localhost:3000 を開きます。

## 自分のピアノ譜を取り込む

「ピアノの楽譜を読み込む」から **非圧縮MusicXML（`.musicxml` / `.xml`、score-partwise形式）** を選びます。楽譜作成ソフトから非圧縮MusicXMLとして書き出してください。PDF・写真・圧縮MXL・MIDIはこの版では未対応です。

- ファイル上限2MB、先頭16拍（四分音符を1拍とする）を使用。
- 音高・臨時記号・音の長さ・和音・休符・複数声部／譜表／パート・タイ・backup/forwardを読み込み。
- 最初のテンポを使用（40〜180 BPMに制限）。拍子が4/4以外なら16拍の4/4グリッドへ配置。
- 原曲再生は取り込んだ音高・開始時刻・長さを維持。テンポ変化・装飾音・ペダル・強弱記号などの表現は再現しません。反復記号は展開せず記譜順に読み込みます。
- 移調楽器のtransposeや微分音は、誤った音で再生しないようエラーにします。実音の楽譜を使用してください。
- 楽譜の音高は固定の5音へ押し込めません。各拍ごとにq0〜q4の音高を割り当て直すため、半音階やオクターブを扱えます。

アプリ内から[歓喜の歌のMusicXML譜例](public/ode-to-joy.musicxml)をダウンロードして、そのまま読み込むこともできます。

## 楽譜 → 量子ゲート → 音楽

各拍に鳴っている音を高い方から最大5音、q0〜q4に割り当てます。毎列 `|00000⟩` を準備し、元の音を鳴らす線に **X** を作用させます。エディターの小さい `X→` がこの準備です。空き線には近い音域の追加ハーモニー候補を割り当てます。セル下の音名がその拍の対応音です。

| 操作 | 量子版で起きること |
| --- | --- |
| 変換のみ | Xによる準備のみ。1拍グリッド化した元の音を再現 |
| ゆらぎ | 1列内の H → Rz(θ) → H で、元の音を確率的に休ませ、追加音を混ぜる |
| デュエット | 1列内の H → CNOT で2本を関連づける |
| リズム崩し | 主旋律の線にHを置き、音／休符を半々にする |

**量子版には、量子効果とは別に1拍への丸め・最大5音・毎拍の弾き直しがあります。** 原曲との差をすべて量子効果とは呼びません。「変換のみ」を比較基準にすると量子ゲートによる変化を分けて聴けます。量子化した開始・終了は最寄りの整数拍に丸め、最短1拍。5音を超えた部分は高音優先で省略します。丸めや省略の数を画面の「楽譜の変換について」に表示します。

## 各列の直後に測定

**1列 = 1拍。ゲート適用 → 5ビット同時測定 → 発音を、4小節で16回実行します。** 120 BPMなら0.5秒ごとです。

- **楽譜モード**：毎列、元の楽譜の音をXで準備し直し、リミックスゲートを作用させて測定。
- **手描きモード**：小節頭で `|00000⟩`。測定後の確定した基底状態を次の列へ引き継ぐ。
- 同時確率分布から5ビットをまとめて1回抽選します。各音の周辺確率から独立に抽選しません。
- ビット表示は `q0 q1 q2 q3 q4`。内部ではq0が最下位ビット。1の線の音が鳴り、0は休符。
- 和音は1拍の選択音を同時に、アルペジオはその拍内で順に発音。`00000` は無音。
- 右の確率は選んだ**拍**の理論値。手描きモードでは、それ以前の測定結果の全分岐を確率で平均しています。直前の1回の実測に条件づけた値ではありません。

列ごとの測定は重ね合わせを壊します。そのため、**異なる列にHを2つ置いても干渉による相殺にはなりません。** Rz単体の直後の測定では音の確率は変わりません。

干渉を楽しむための **∿（INT）= H → Rz → H**、もつれを作るための **PAIR = H → CNOT** は、1列内で測定前に完結する複合ゲートです。通常のCNOTも残していますが、測定済みの基底入力へのCNOTは条件付き反転であり、単独でもつれは作りません。

## 保存と互換性

IndexedDBへ自動保存。JSONには元の楽譜の音符、回路、音楽設定、任意の16測定値を保存します。「演奏を固定」は新しい16拍を測定して保持し、直前の演奏を録音する操作ではありません。ゲート変更で固定を解除。作品名・テンポ・音色の変更では保持します。

旧version 1のJSON／自動保存も読み込めます。回路と音楽設定をversion 2に移行し、旧来の4小節分の固定結果は解除します。測定仕様が変わるため旧作品の音は同一にはなりません。

作品・楽譜はブラウザ内に保存し、サーバーへ送信しません。別端末への移動やバックアップにはJSONをご利用ください。ブラウザが背景に移ると再生を停止します。

## 開発・検証

```bash
npm run check
npm test
npm run build   # dist/ に静的配信ファイルを生成
npm start       # dist/ を配信。PORT環境変数対応
```

ブラウザ検証用ツールは、アプリの実行・ビルドには不要です。

```bash
npm install --no-save --package-lock=false playwright@1.58.2
npx playwright install chromium
npm run build
npm start
# 別ターミナルで
npm run test:e2e
```

GitHub Actionsで構文検査・単体テスト・ビルド・Chromium操作テストを実行。MusicXMLの実ファイル読み込み、複数声部・タイ・テンポ、A/B交互再生、毎拍の測定、保存・復元、スマートフォン幅を検証します。画面キャプチャと配信ファイルはActionsのArtifactsに保存します。実際の聴感評価とSafari／iOS実機の確認は別途必要です。

## デプロイナウで公開

ルートに `index.html` があるため、GitHub連携で **「静的サイト」・ブランチ `main`** を指定できます。Next.jsは選ばないでください。

1. デプロイナウの新規作成からGitHubを接続。
2. `hu-umaru/deploynow_contest` を選択。
3. フレームワーク「静的サイト」、ブランチ `main`、サブドメインを指定して作成。
4. 公開URLで原曲と量子版の再生を確認。

配信ファイルだけを公開するなら、`npm run build` 後の `dist/` をブラウザからアップロードできます。リポジトリのルートを静的公開するとREADME・testsなどの非ドットファイルも配信対象になります。

公式手順：[GitHub連携](https://deploy.lolipop.jp/docs/quickstart/github) / [静的サイト](https://deploy.lolipop.jp/docs/frameworks/static)。このリポジトリのCIは検証用です。ホスティングの作成・応募フォーム送信は行いません。

## 構成

| モジュール | 役割 |
| --- | --- |
| `src/musicxml.js` | MusicXML解析、譜例、各拍の音高・X準備への変換 |
| `src/quantum.js` | Float64複素状態、単体／複合ゲート、1列の回路 |
| `src/sequencer.js` | 列ごとの射影測定、測定結果の引継ぎ、分岐を含む理論確率 |
| `src/project.js` | version 2検証／旧形式移行、ゲート配置、リミックス、音符イベント |
| `src/audio.js` | 拍単位の音声クロック、A/B再生、合成音、停止処理 |
| `src/storage.js` | IndexedDB |
| `src/app.js` | エディター、楽譜プレビュー、操作履歴、保存 |

設計の詳細は[architecture.md](docs/architecture.md)。依存ゼロのES Modules / Web Audio構成で、量子・音楽・保存ロジックはUIから分離しています。
