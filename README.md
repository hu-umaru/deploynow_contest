# 量子ビート工房 / Quantum Beat Studio

**音符のかわりに、量子ゲートを。測るたびに生まれる、あなただけのフレーズ。**

デプロイナウコンテスト向けの、5量子ビット × 4小節のブラウザ作曲アプリです。外部API・アカウント・有料音源は不要。量子実機ではなく、ブラウザ内の状態ベクトルシミュレーションを使います。

## 起動

Node.js 22以上を用意してください。アプリの依存パッケージはありません。

```bash
git clone https://github.com/hu-umaru/deploynow_contest.git
cd deploynow_contest
npm ci
npm run dev
```

http://localhost:3000 を開き、「再生する」を押します。最初から回路が入っているので、そのまま聴けます。スマートフォンでは五線譜を横にスクロールできます。

## 実装済み

- 五線譜の5本線に q0〜q4 を対応させたゲートエディター
- 4小節それぞれに4列の H / X / Rz / CNOT、消しゴム、元に戻す・やり直す
- Rz角度の指定、制御・標的を2クリックで選ぶCNOT
- 32状態の複素振幅、測定前の周辺確率・上位6通りの同時確率・振幅の位相表示
- 各小節ごとの5ビット同時測定と4小節ループ
- 和音／アルペジオ、3つのペンタトニックスケール、2音色、テンポ・音量
- 毎ループ再測定するライブ演奏／4小節の測定値を保持する固定演奏
- IndexedDBへの自動保存、JSONの書き出し・読み込み、入力検証
- 重ね合わせ・もつれ・干渉を体験できる3プリセット
- レスポンシブ画面、キーボード操作、あそびかた、バックグラウンド時の再生停止

「演奏を固定」は**新しい4小節を測定して**保存します。再生途中の履歴をそのまま録音する機能ではありません。回路を編集すると固定を解除します。作品名・テンポ・音色・音階を変えても測定値は保持します。

## まず試すこと

1. **量子のスケッチ**：再生するたびに違うフレーズを聴く。
2. **もつれたメロディ**：H + CNOTで2音が一緒に鳴る／休むことを観察する。
3. **干渉のグラデーション**：H → Rz(θ) → H。4小節の θ = 0°, 90°, 180°, 270° に対し、E4の発音確率は0%, 50%, 100%, 50%。

同じ線にHを2つ続けると元の状態に戻ります。Rz単体で測定確率が変わるわけではありません。

## 量子と音楽の約束

- 小節は常に `|00000⟩` から始まり、回路を左から右へ適用します。
- **小節の開始時**に、その小節の回路を計算して1回測定し、結果をその小節で演奏します。4列は回路の演算順であり、4拍の発音位置ではありません。
- 5ビットを同時に1回サンプリングします。周辺確率から独立に抽選すると量子相関が失われるため、その実装はしません。
- 表示順は上から `q0 q1 q2 q3 q4`。内部の整数ではq0が最下位ビットです。`10000` はq0だけが1、内部整数では1です。
- 1の線の音が鳴り、0は休符。和音は選ばれた全音を同時に、アルペジオは選ばれた音を順に8分音符で8回鳴らします。`00000` は無音です。
- 小節間の量子状態は引き継ぎません。測定後の状態は破棄し、次の小節は再初期化します。
- CNOTの制御〜標的間の線も同じ列の占有領域です。重ねてゲートを置くと既存の占有ゲートを置換します。

## 開発・検証

```bash
npm run check   # JavaScript構文検査
npm test        # Node組み込みテスト
npm run build   # dist/ に静的配信ファイルを生成
npm start       # dist/ を配信。PORT環境変数対応
```

ブラウザ統合テストは開発用にPlaywrightを追加します。アプリの実行・ビルドには必要ありません。

```bash
npm install --no-save --package-lock=false playwright@1.58.2
npx playwright install chromium
npm run build
npm start
# 別のターミナルで
npm run test:e2e
```

GitHub Actionsでは構文検査・単体テスト・ビルド・Chromium操作テストを実行し、画面キャプチャと静的配信ファイルをArtifactsに保存します。実ブラウザでの音質判断、Safari／iOS実機での最終確認は別途必要です。

## デプロイナウで公開

このリポジトリはルートに `index.html` があるため、**GitHub連携でフレームワーク「静的サイト」・ブランチ `main`** を選べます。Next.jsを選ばないでください。

1. デプロイナウの新規作成からGitHubを接続。
2. `hu-umaru/deploynow_contest` を選択。
3. フレームワークを「静的サイト」、ブランチを `main` に設定。
4. サブドメインを選んで作成し、発行されたURLで音声再生を確認。

静的サイトとしてルートを公開する場合、READMEやtestsなどの非ドットファイルも公開対象になります。現時点で秘密情報はありません。配信ファイルだけを公開したい場合は `npm run build` 後の `dist/` をブラウザからアップロードしてください。

公式手順：[GitHub連携](https://deploy.lolipop.jp/docs/quickstart/github) / [静的サイト](https://deploy.lolipop.jp/docs/frameworks/static)。公開には利用者自身のデプロイナウの連携・設定が必要です。本リポジトリのCIは検証用で、ホスティングの新規作成や応募フォームの送信は行いません。

## 構成

| ファイル | 役割 |
| --- | --- |
| `src/quantum.js` | Float64の複素状態ベクトル、ゲート、同時測定 |
| `src/project.js` | プリセット、スキーマ検証、ゲート配置、音への変換 |
| `src/audio.js` | Web Audio、音声クロックに基づくスケジュール、停止処理 |
| `src/storage.js` | IndexedDBの読込・保存 |
| `src/app.js` | UI状態、編集履歴、保存待ち、各モジュールの接続 |
| `src/style.css` | レスポンシブUI |
| `tests/` | 量子・データ・音楽・ブラウザの回帰検証 |
| `docs/architecture.md` | 設計上の判断と次の拡張候補 |

初期案のNext.js / React / TypeScript / Tone.jsに対し、このMVPは依存ゼロのES Modules / Web Audioで実装しました。開発環境からnpm配布元へ接続できない制約下でも、実装した量子計算を実行検証でき、静的ホスティングで配信できるためです。量子・音楽・保存のロジックはUIから分離しており、将来のUIフレームワーク移行時に再利用できます。

## 保存とプライバシー

作品はこのブラウザのIndexedDBに保存します。サーバー送信・解析・アカウントはありません。ブラウザデータの削除や別の端末には引き継がれないため、作品を残す場合はJSONを保存してください。Web Audioはユーザーの再生操作後に開始します。
